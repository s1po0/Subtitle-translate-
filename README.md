# ڕیزنووس — Kurdish subtitle translator

Client-side Vite/React subtitle translation to Central Kurdish (`ckb`). Upload SRT, VTT, ASS or SSA; translate with the default unofficial, keyless Google endpoint; review and download the result. Optionally configure a Google Cloud Translation API v2 key in Settings for the official provider. The key stays in browser localStorage and is sent only to Google. Enable the Cloud Translation API and restrict the key by HTTP referrer and API in Google Cloud. Translation is billable under Google's terms. Subtitle text is sent to the selected Google service.

The default unofficial option may be blocked by CORS, rate-limited, or change without notice; it cannot be guaranteed to work in every browser or region. No relay is deployed. Encoding detection for legacy encodings is heuristic and may be wrong. Google Cloud batches separate cue strings; it does not guarantee context across cue boundaries. Review output, especially ASS conversions and split sentences. WebVTT metadata blocks are skipped. For incomplete translations, export asks for confirmation and uses the original text for missing entries. ASS conversion to SRT/VTT can retain player-specific override syntax. Timestamp precision may change when converting between formats (ASS uses centiseconds; rounding carries into the next second). Never use a key in a committed environment file.

Build: `npm install && npm run build`; checks: `npm run lint && npm test`. An opt-in live smoke test uses `GOOGLE_TRANSLATE_API_KEY` in the environment; it may incur charges. The default suite does not contact Google. Deploy the build directory `dist` with SPA fallback routing (e.g. Lovable/Vite-compatible hosting).

## Android

The Capacitor Android project uses application ID `com.rizhnus.subtitle`. Its release workflow builds and verifies a signed APK only when `ANDROID_KEYSTORE_BASE64` and `ANDROID_KEYSTORE_PASSWORD` are configured as GitHub Actions secrets. The signing key backup belongs in private storage, never in Git. Android exports are offered through the system share/save dialog. Android builds and device behavior require separate verification; the unofficial translation service can still be blocked by network or WebView CORS.

You can select multiple subtitle files, translate them in one queue, review each file, and download a ZIP. Files with pending or failed cues export their original text after confirmation. Android uses native HTTP for the unofficial Google request to avoid browser CORS, but Google can still block or change this endpoint. GitHub Actions installs the APK and runs layout and foreground-service checks on an Android emulator. Those checks do not exercise native translation or file selection end-to-end.

The default provider uses Google's undocumented website-translation widget endpoint with its public widget key, in batches of separate HTML-protected cues. It validates response count and protected markers. This key is public and is not a user Cloud API key. Google may change or rate-limit the service; unlimited use is not guaranteed. A CI smoke test sends synthetic sample sentences to Google; it does not measure reliability in the user's region or Android native transport.

Android translation starts a foreground notification and holds a time-limited CPU wake lock while the WebView is translating. Going Home can keep the session running, but Android may pause or kill the app, stop it after system time limits, or restrict background network access. Swiping the app away or force-stopping it stops the job. The current file, edits and completed rows are saved locally in IndexedDB for recovery; reopening the app and starting translation again uses the cache for completed cues. No background execution is promised after process death or reboot. The emulator test checks foreground-service survival after Home, not a live Google translation.

Android's file picker shows all file types because subtitle extensions are not consistently recognized by Android MIME filters; unsupported files are rejected after selection. Select several files with a long press, or add them in multiple visits to the picker. Existing edits stay in the queue; each can be reviewed separately or exported together as a ZIP.

The public pages of subtitlestranslator.com and translatesubtitles.co describe their multi-file workflows; the latter says it uses Google Translate. No private API or source code from those sites is used. REA was reviewed but its live-site tooling is unavailable in this environment; the websites’ internal engine and accuracy are not verified.

## Review and progress

Each file in the queue shows completed and failed cue counts. The review filter can highlight pending or failed cues, unusually fast reading speed, and source text that appears unchanged in the output. These are heuristic hints, not a quality or language guarantee; names and valid unchanged words can be flagged. The original subtitles stay on the device; translation text is sent to Google.

### Video captions (experimental)
Android can select a local video with an audio track up to 30 minutes. MediaExtractor/MediaCodec decode at most two minutes at a time, downmixing to 16 kHz mono WAV. Chunks overlap by up to two seconds at each boundary; words are assigned by their midpoint and obvious overlapping duplicate words are removed. This reduces edge truncation risk but does not guarantee perfect boundaries. Each chunk is sent to Puter/Gemini for word-timed transcription; timestamps are offset, an SRT is added to the queue and Google translation is started automatically. Review and export the separate SRT. The source video is not uploaded. On the web, decoding is limited to 3 minutes and 75 MiB because it uses browser memory. Codec support, duration metadata and device capabilities vary.

This requires explicit consent, Puter login and an internet connection; usage may cost money and is not unlimited. Gemini can omit, mistranscribe or mistime words, especially across chunk boundaries. Empty/invalid timestamps are rejected where text is returned and a rough mismatch warning is displayed, but neither proves completeness. Google receives the transcribed text. Do not submit confidential material without permission. Keep the app open: transcription does not run in the background. Completed chunks are stored in a single local IndexedDB checkpoint, containing recognized text and timing. On Android, select the same video again after reopening; its full SHA-256 fingerprint and duration must match before the checkpoint is restored. Hashing large files takes time but uses bounded memory. Web files are hashed in memory. A button deletes this checkpoint. Storage can fail or be cleared; a failed or interrupted request may still incur provider charges, and the last completed request might be sent again if it was not saved. A different video replaces the checkpoint after its first completed chunk. Temporary WAV files are kept in the app's private cache only while a chunk is read, and are deleted afterwards or at next launch. Popup authentication and real paid STT depend on external services and must be verified on a user's device. Gemini 3.5 Transcribe does not currently list Central Kurdish among its supported input languages; this pipeline is intended for foreign-language input translated into Sorani, not reliable Sorani speech recognition.

Sources: https://docs.puter.com/AI/speech2txt/ documents a 10 MiB limit, word timings, and 8,192 output-token limit. https://docs.puter.com/user-pays-model/ describes usage and billing. Android popup guidance: https://developer.adobe.com/express/embed-sdk/docs/guides/concepts/mobile-web-support-webview.

### RTL punctuation in exported subtitles
RTL direction hints are enabled by default, including for settings saved by versions before 2.7. Each nonempty translated text line is wrapped with balanced Unicode RLE/PDF and RLM hints; this retains logical text order and helps punctuation display correctly in both LTR- and RTL-based players. ASS override tags, ASS line breaks, subtitle timing and untranslated fallback lines remain untouched. Unicode bidi rendering and Arabic-script shaping depend on the player and font; no marker can fix players that lack RTL support. If a player displays marks badly, disable «ڕاستکردنەوەی خاڵ و ئاراستە» in settings and export again. Existing user-supplied directional controls are not stripped.

### Square brackets
Square-bracket delimiters are protected, but words inside them are sent for translation, including descriptions such as `[music]`. Tags, music symbols and explicitly protected glossary terms remain protected. Invalid or reordered bracket markers fail rather than being silently dropped. Existing completed files can be retranslated using the per-file retry button; edited rows are preserved. Translation quality and the placement of the words inside brackets still require review.

### Startup and appearance
The Android launcher and splash use the Rizhnus icon and a dark background. The local app bundles its font and has an on-screen retry if the web interface fails to load; this cannot resolve every Android WebView or native startup failure. Updating Android System WebView and reporting the Android version can help diagnose persistent startup problems.

### Experimental automatic sentence context
The default keyless Google mode (and optional Cloud mode) conservatively joins two adjacent English cues only when the first looks unfinished and the second begins with a lowercase continuation, timing is close, and neither contains formatting, sound markers or protected glossary terms. It sends the combined text to the same provider, protects the boundary, validates it and falls back to individual translations if it is lost or empty. Original timestamps remain unchanged. Reordering across the boundary can still place words in the wrong cue; translated meaning and timing require review. Disable the feature in settings if results are worse. Other languages and complex cues remain individually translated. Completed files must be retranslated to use it; edits are preserved. This heuristic does not run Claude skills, supply film knowledge, or guarantee better meaning.

### Kurmanji in Arabic script (approximate, not guaranteed Badini)
Before translating, choose either Sorani or “Kurmanji in Arabic script (close to Badini)”. The optional mode requests Google's Kurmanji (`ku`), then applies an independently implemented, approximate Hawar-to-Arabic script mapping to the translated text locally. It does not translate Kurmanji vocabulary into Badini, and vowel spelling, names, untranslated fragments, grammar and punctuation may need correction. Proper nouns can be protected in the glossary. The output is not guaranteed Badini and must be reviewed. Formatting placeholders, glossary terms and timestamps are preserved; unmodified source cues are not transliterated. Cache keys distinguish targets and filenames use `.ku-Arab` rather than `.ckb`. To prevent mixing languages or overwriting edits, the target cannot be changed while the queue contains completed or edited rows; export and remove those files first. Old saved sessions default to Sorani.

### Approximate names in Arabic-to-Sorani output
For Arabic-script source cues translated to Sorani (Arabic selected or auto), capitalized Latin words in otherwise Kurdish-script output are heuristically written in Arabic script, e.g. `Tariq` → `تاریق`. This is a spelling approximation, **not translation** or reliable name recognition: some ordinary words may be misidentified, names and vowel spellings may be wrong, and lowercase names, acronyms or fully Latin output are not converted. Protected glossary terms, markup, URLs and Latin text already in the source are left alone. The feature can be disabled in settings. Review and edit names; retranslate existing rows to apply a changed setting (edited rows are preserved). It does not repair all English words or guarantee Sorani meaning.
